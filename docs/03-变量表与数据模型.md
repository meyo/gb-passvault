# 03 · 变量表与数据模型

> 版本说明：GB Studio **4.3 及更早**：项目固定有 512 个全局变量（`$Variable0`…`$Variable511`），
> 直接按下面的表**按编号顺序重命名**即可（编号就是隐式"内存地址"）。
> **4.4 开发版**起变量按需创建，请为下表每一项都真实创建变量，保证编号连续。

---

## 1. 总览

| 区块 | 变量编号 | 数量 | 用途 |
|------|---------|------|------|
| 系统状态区 | 0–33 | 34 | 启动、PIN、UI 状态、键盘光标、临时值 |
| `$DB_LABEL` 区 | 34–129 | 96 | 8 槽 × 12 字符 账号/标签（字符编码） |
| `$DB_SECRET` 区 | 130–225 | 96 | 8 槽 × 12 字符 密码（字符编码） |
| `$DB_LENL` 区 | 226–233 | 8 | 每槽标签长度（0–12） |
| `$DB_LENS` 区 | 234–241 | 8 | 每槽密码长度（0–12） |
| `$DB_FLAG` 区 | 242–249 | 8 | 每槽状态（Flag 1 = 已存账号） |
| `$D0`–`$D11` 编辑缓冲 | 250–261 | 12 | 当前正在编辑/显示的 12 个字符 |
| 合计 | | **262 / 512** | 余量充足 |

> **核心约束：`$DB_LABEL`、`$DB_SECRET`、`$DB_LENL`、`$DB_LENS`、`$DB_FLAG`、
> `$PIN_BUF0`、`$D0` 都是"连续变量段"。**
> 数组读写事件（`PM: Array Write / Read`）依赖"基址 + 下标"的间接寻址，
> 元素必须紧挨着编号排列。重命名时**不要跳号、不要插队**。

## 2. 系统状态区（0–33）

| 编号 | 建议名 | 说明 |
|------|--------|------|
| 0 | `$BOOTED` | 0 = 首次开机未初始化；1 = 已有存档 |
| 1–4 | `$PIN0`–`$PIN3` | 存档中的 PIN（以 +7 混淆保存） |
| 5 | `$PIN_TRY` | 连续输错次数（≥3 触发"锁定"彩蛋） |
| 6 | `$PIN_MODE` | 0 = 解锁校验；1 = 设置新 PIN；2 = 确认新 PIN |
| 7–10 | `$PIN_BUF0`–`$PIN_BUF3` | PIN 输入缓冲（连续段，配合数组写入） |
| 11 | `$PIN_LEN` | PIN 已输入位数（0–4） |
| 12–15 | `$PIN_TMP0`–`$PIN_TMP3` | 校验收到的解码值 / 设置新 PIN 的暂存 |
| 16 | `$SCRATCH` | 数组读写的临时地址变量（不可与其它临时量共用） |

| 23 | `$SEL_COL` | 光标列（0–7） |
| 24 | `$SLOT` | 当前账号槽（0–7） |
| 25 | `$FIELD` | 0 = 标签，1 = 密码 |
| 26 | `$LEN_LBL` | 标签字段长度（0–12，编辑时） |
| 27 | `$LEN_SEC` | 密码字段长度（0–12，编辑时） |
| 28 | `$LEN` | 当前字段长度（$FIELD 对应值） |
| 29 | `$REVEAL` | 详情页 0 = 掩码，1 = 显示 |
| 30 | `$CHOICE` | 菜单/列表选择结果 |
| 31 | `$SCRAMBLE` | 混淆密钥常量（初始化时设为 165） |
| 32–33 | `$MV_R`、`$MV_C` | 键盘光标移动方向（行/列增量，±1 或 0） |

## 3. 数据库区

### 3.1 标签区 `$DB_LABEL`（34–129，共 96 个）

槽位 `s`（0–7）、第 `p` 个字符（0–11）的变量编号 = `34 + s*12 + p`。

| 槽位 | 编号区间 | 第一个字符的建议变量名 |
|------|---------|----------------------|
| 0 | 34–45 | `$DB_LABEL_0_0` … `$DB_LABEL_0_11` |
| 1 | 46–57 | `$DB_LABEL_1_0` … |
| … | … | … |
| 7 | 118–129 | `$DB_LABEL_7_0` … |

### 3.2 密码区 `$DB_SECRET`（130–225，共 96 个）

同样：`130 + s*12 + p`，命名 `$DB_SECRET_s_p`。

### 3.3 长度区

- `$DB_LENL_0`–`$DB_LENL_7`（226–233）：标签长度
- `$DB_LENS_0`–`$DB_LENS_7`（234–241）：密码长度

### 3.4 状态区 `$DB_FLAG`（242–249）

`$DB_FLAG_0` … `$DB_FLAG_7`，每槽 1 字节；用 `Variable Flags Add` 设置
Flag 1（= 1）表示"已存账号"。

### 3.5 编辑显示缓冲 `$D0`–`$D11`（250–261）

进入编辑/详情页时，把当前槽的 12 个字符用数组读取加载进来，
文本事件统一引用 `%c$D0%c$D1…%c$D11` 渲染（固定变量，避免"动态变量名"问题）。

---

## 4. 数据编码约定

1. **字符 = 编码数字**。一个变量存一个字符（GB 字体为 ASCII 子集）：
   - `32` = 空格（空位填充值，**初始化把整段填 32**）；
   - `48–57` = `0`–`9`；`65–90` = `A`–`Z`；
   - `33 !`、`63 ?`、`64 @`、`35 #`、`36 $`、`37 %`、`95 _`、`45 -`、`46 .`、`47 /`。
2. **显示**：文本事件里用 `%c` 前缀 + 变量按字符码渲染：
   `SECRET: %c$D0%c$D1%c$D2…%c$D11`
3. **空位规则**：$D 缓冲中，位置 ≥ `$LEN` 的格子必须保持 32（删除/清空时显式补 32），
   这样整行重绘不会残留旧字符。
4. **PIN 混淆**：存档时存 `PIN + 7`，校验时 `-7` 还原。
   进阶：插件 `PM: XOR Mix` 对字符做异或（示例密钥 165）。
5. **空槽判定**：读 `$DB_FLAG_s` 的 Flag 1。列表界面固定显示 8 项，
   未用槽显示空白即可（复古记事本风格）。

---

## 5. 容量与存档（SRAM）说明

- `Game Data Save` 会把**全部变量 + 引擎运行状态**写进 SRAM 的存档槽（共 3 个槽位）。
  本项目数据 ≈ 262 个变量 ≈ 524 字节，加上引擎状态后单槽存档约 1–2 KB，
  远小于 SRAM 单 Bank 的 8 KB（卡带默认 32 KB SRAM 绰绰有余）。
- 变量越多，存档 blob 越大；注意力不要堆无用的变量。
- 建议**只在数据变化时**存档（编辑完成、改 PIN 时），不要每帧存——SRAM 写入有寿命限制。
- 3 个存档槽不要拿来做"多用户"：本项目固定 8 个账号槽放在一个存档里，
  "多套数据库"会显著放大事件量，不属于本框架范围。
