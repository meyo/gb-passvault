## 2. 技术栈

- **语言/工具链**：GBDK-2020 4.5.0（SDCC C + `lcc`），预编译包位置 `tools/gbdk/`
- **渲染**：BG tile 图形界面；常规文字用 96 个正色字模 + 开机生成的 96 个反白字模，
  V0.3.5/V0.3.6 PIN 画面另用 9-slice 图形 tile（键帽/分格框/标题/整字数字）绘制；V0.3.6 菜单/列表/设置/恢复画面也使用 9-slice 面板，纯 BG、无 sprite；
  4 阶绿色调色板（BGP=0x9C）。
- **音频**：无（仍未使用声音硬件）
- **存档**：MBC1 卡带 RAM + 电池；**32KB SRAM（4×8KB 存储体，RAM banking）**
  - v0.3.2–v0.3.6 使用 **21,712 字节**：头部 16B + 255×80B 槽位区（20,416B）+ 回收站（16B 头 + 16×80B，位于 20,416..21,711，仍在存储体 2）；
  - v0.3 旧档为 12,001 字节（16B + 255×47B），跨存储体 0/1；
  - 迁移暂存区使用存储体 3 的空闲高区（12,368..32,767），迁移完成后清零（回收站与之重叠但迁移前必为空）。
- **测试**：serverboy（JS 无头模拟器）+ 自研端到端断言脚本
- **构建**：`./build.sh`（编译 + ROM 头部自检一步完成）

## 4. 功能地图（用户视角）

### 4.1 开机流程

```
上电
 └─ 标题画面 "GB PASSWORD VAULT / PRESS START"（V0.3.6）
     [START]
      └─ vault_load()  读 SRAM（MAGIC + 全局校验和；只读，不写）
          ├─ 当前格式 PMG4 且校验通过
          │    ├─ 未设置过 PIN → FIRST TIME SETUP（提示 1.5 秒）
          │    │     └─ NEW PIN → CONFIRM PIN（均为 6 位）
          │    │        (不一致 → "PIN MISMATCH" 从头重输; 同时清空 255 槽全区)
          │    │        └─ 写入 SRAM → 主菜单
          │    └─ 已设置 PIN → ENTER PIN（6 位解锁画面）
          │          ├─ 正确 → 主菜单（顺带清零错误计数）
          │          └─ 错误 ×3 → SYSTEM LOCKED（彩蛋锁定页）
          │                ├─ 按住 A+B+SELECT+START 连续 3.000 秒
          │                │    → 全库擦除（头部+槽位区）→ 回到首次设置（NEW PIN）
          │                └─ OR POWER OFF：关机重开仍锁定（错误次数已持久化）
          ├─ PMG4 校验失败 → SAVE CORRUPT
          │    ├─ 只读扫描可识别记录，显示数量
          │    ├─ A=RETRY 重新读取
          │    └─ START → 确认 → A=显式擦除 → FIRST TIME SETUP
          ├─ 未知 MAGIC → UNSUPPORTED SAVE（同样只能重试或显式擦除）
          └─ 检测到 v0.3（PMG3）且旧校验和通过
               ├─ 输入旧 4 位 PIN（错误次数沿用旧档，满 3 次同样锁定/擦除）
               ├─ 设置新 6 位 PIN（两次确认；旧 4 位 PIN 不会自动补零）
               ├─ "UPGRADING SAVE / DO NOT POWER OFF"
               │    ├─ 阶段 1：旧档 → 存储体 3 空闲高区（旧数据不动，断电可重来）
               │    ├─ 阶段 2：暂存区 → 新布局正式位置（升序安全搬运）
               │    ├─ 写 PMG4 头（新 PIN / 校验和）
               │    └─ 清零暂存区
               └─ "SAVE UPGRADED" → 直接进入主菜单（无需再次解锁）
```

### 4.2 主菜单

```
VAULT MENU（6 项）
 ├─ VIEW ACCOUNTS ─► 账号列表（12 行滚动窗口，标题右侧 "nnn/255" 位置）
 │      ├─ [上下] 逐条移动；按住不放连续滚动（长按约 0.4s 后每 0.13s 一格）
 │      ├─ [左右] 整页翻 12 条（255 槽快速巡航；到底自动钳位）
 │      ├─ [SELECT] 切换整表显示「标签 ⇄ 用户名」（空用户名显示 `-`，模式持久化）
 │      ├─ [A] 打开详情：按住 A 显示密码明文（两行），松开恢复打码
 │      │        [SELECT+START 同时按住] 编辑该槽位
 │      │        [START] 单独按 = 删除该槽位（二次确认后进回收站）  [B] 返回列表
 │      └─ [A] 空白槽 = 直接进入该槽的新建流程
 ├─ ADD ACCOUNT ──► LABEL (≤20) ─► USERNAME (≤20, 可留空) ─► PASSWORD (≤36)
 │                  (自动占用第一个空槽; 满 255 时提示 VAULT FULL)
 ├─ CHANGE PIN ───► OLD PIN → NEW PIN → CONFIRM PIN（6 位）─► 保存（PIN UPDATED）；
 │                  旧 PIN 错误则返回菜单且不写存档；此画面同样参与自动锁屏（新 PIN 不保存）
 ├─ LOCK VAULT ───► 回到解锁画面
 ├─ RECYCLE BIN ──► 最近删除的 16 条记录（最新在前）[A] 恢复 [SELECT] 永久删除单条
 │                  [START] 清空全部（二次确认） [B] 返回
 └─ SETTINGS ─────► PASSWORD LENGTH (12/16/24/32) / SYMBOLS (ON/OFF) / AUTO-LOCK (1/2/3/5/10 MIN)
                    [A] 或 [左右] 切换，改动立即存盘并生效 [B] 返回
```

列表选中行的标签超过 14 字符时，会以**跑马灯**来回显示完整标签（V0.3.6 列表窗口为 14 字符，左右边框保留）：

- 起始停顿约 0.5 秒 → 每格约 0.125 秒左移 → 尾部停顿约 0.75 秒 → 反向回滚；
- 只重绘选中行；切换条目立即复位到标签头部；
- 使用 TIMA 4096Hz 回绕计时，不依赖 HALT/中断。

详情页布局（v0.3.1）：

```
SLOT nnn/255
LABEL:
<20 字符标签>
USER:
<20 字符用户名>
PASS:
<密码第 1 行: 20 格>
<密码第 2 行: 16 格>
A=REVEAL B=BACK
SEL+START=EDIT
START=DELETE
```

编辑流程（详情页 SELECT+START）：

- LABEL → USERNAME → PASSWORD 三页均**预填原值**；
- START = 保存并进入下一页 / 最终保存（密码不能为空；用户名可清空）；
- 标签页 / 用户名页 SELECT = 取消整个编辑；密码页 SELECT = 生成/重掷随机密码；
- 保存后 toast `UPDATED`，详情页立即刷新；
- 单独按 START 仍是删除入口，组合键不会误触删除。

## 5. 数据模型（SRAM 布局）

**MBC1 控制寄存器**（32KB = 4 个 8KB 存储体，RAM banking）：

- `0x0000 ← 0x0A / 0x00`：RAMG 开关；
- `0x6000 ← 0x01`：上电一次性写入 —— MBC1 **模式 1（RAM banking 模式）**；
- `0x4000 ← 体号 0..3`：模式 1 下选择 RAM 存储体（`data & 0x03`）；
- 数据窗口固定 `0xA000-0xBFFF`（每体 8KB）。

> ⚠️ MBC1 的 0x4000 是**双职能**寄存器：模式 0 时它是 ROM bank 高位，模式 1 时
> 才是 RAM 存储体选择。**不写 0x6000=1 直接写 0x4000 会破坏 ROM bank → 跑飞**。
> serverboy 与真机行为一致（mode 0 下 0x4000 走 ROM bank 分支、RAM 强制回体 0）。

**平面地址约定**（本 ROM 私有）：`平面地址 = 体号×8192 + 体内偏移`；
`rb()/wb()` 对每个字节自动切体（体号缓存在 `cur_bank`，只在跨体时写寄存器）。

### 5.1 当前格式 v0.3.2（PMG4）

| 平面偏移 | 长度 | 内容 |
|---|---|---|
| 0x0000 | 4 | MAGIC `"PMG4"` |
| 0x0004 | 6 | PIN 混淆值：`(digit + 7) % 10` |
| 0x000A | 1 | 连续错误次数（≥3 触发锁定） |
| 0x000B | 1 | 全局 XOR 校验和（种子 0xA5，**跳过自身**） |
| 0x000C | 1 | FLAGS：bit0 = 已设置 PIN |
| 0x000D | 3 | 设置：0x0D = 生成长度(bit0-1: 12/16/24/32) \| 符号(bit2) \| 有效位(bit7)；0x0E = 锁屏时长索引(1/2/3/5/10 分钟)；0x0F = 列表视图(0=标签, 1=用户名) |
| 0x0010 | 20400 | 槽位区：**255 × 80 字节**（16 + 255×80 = 20,416，跨存储体 0/1/2） |

> v0.3.1 存档的 0x0D 有效位为 0，加载时使用默认设置（16 位 / 符号 ON / 3 分钟 / 标签视图），
> 升级 v0.3.2 后首次改动设置即写入。

单个槽位记录（80 字节）：

```
[0]       used      0xA5 = 已用, 0 = 空
[1]       llen      标签长度 (≤20)
[2..21]   label[20] 标签 (char 原码, 不足部分 0)
[22]      ulen      用户名长度 (≤20)
[23..42]  user[20]  用户名 (可空)
[43]      plen      密码长度 (≤36)
[44..79]  pass[36]  密码
```

- **校验和算法**：`c = 0xA5; c ^= 平面 0x000..0x00F 跳过 0x00B; c ^= 平面 0x010..20415`
  （共 20,416 字节；循环变量用 `uint16_t`）。
- **读写策略**：不做整库 WRAM 镜像（20KB 装不进 8KB WRAM）。全部按需定点读写：
  `slot_read/slot_write/slot_clear`（含跨体自动切换）、`find_empty`（线性扫描 255 条）。
- **v0.3.2 增量校验和（保存速度）**：XOR 可增量维护，RAM 里缓存当前校验和 `vault_chk`；
  槽位写入/清空按“旧字节 XOR 新字节”差分更新，头部设置改动增量更新 3 字节，
  保存时 `vault_commit()` 只把缓存值写回 0x000B，**不再全量重算 20KB**。
  上电 `vault_load()` 仍全量计算一次并校验；迁移/首次设置/擦除后由 `header_save()` 全量重算。
- **性能优化（v0.3.1 保留）**：`chk_calc()` 与 `vault_clear_slots()` 按 8KB 存储体
  直接访问 `0xA000` 窗口（校验和只切体 3 次；清空用 `memset` 分体处理）；
  v0.3.2 的 `vault_clear_slots()` 会清空全部 4 个体（含回收站与迁移暂存残区）。
- **存档文件布局**：电池备份 / serverboy `getSaveData()` 即 32KB 平铺，
  索引与平面地址一一对应（`存档[i] = 平面地址 i`），测试脚本直接按 `16 + i×80` 取记录。
- 校验和只防意外损坏/半写，**不是防篡改手段**。

### 5.2 旧格式 v0.3（PMG3，仅用于迁移）

| 平面偏移 | 长度 | 内容 |
|---|---|---|
| 0x0000 | 4 | MAGIC `"PMG3"` |
| 0x0004 | 4 | PIN 混淆值 |
| 0x0008 | 1 | 旧错误次数 |
| 0x0009 | 1 | 旧全局校验和（跳过自身） |
| 0x000A | 1 | 旧 FLAGS |
| 0x0010 | 11985 | 旧槽位区：255 × 47 字节（旧记录区总长 12,001） |

旧记录：`used(1) + llen(1) + label[8] + plen(1) + pass[36]`，无用户名。

### 5.3 迁移算法（v0.3 → v0.3.1）

1. **识别**：MAGIC 为 `PMG3` 且旧校验和（0..12000，跳过 0x0009）通过；否则视为空档。
2. **验证旧 PIN**：输入旧 4 位 PIN；错误次数写回旧档（重算旧校验和），满 3 次沿用锁定彩蛋并擦除。
3. **设置新 PIN**：输入两次 6 位 PIN，不把旧 4 位补零。
4. **阶段 1（不破坏旧档）**：逐条读取旧记录，转换成新 80B 布局，写入
   `12,368..32,767` 的暂存区（255×80 = 20,400B，正好占满存储体 1 的尾部 + 2 + 3）。
   旧档 0..12,000 完全未动；此阶段断电，下次开机仍识别为 PMG3，可重来。
5. **阶段 2**：按槽位升序，把暂存记录搬到 `16 + i×80`。目标地址始终低于未读源地址，
   不会覆盖尚未搬运的数据。
6. **写入新头**：MAGIC4、新 PIN、tries=0、FLAGS=1，重算 20,416B 校验和。
7. **清零暂存区**：消除密码副本；然后进入主菜单。

安全性说明：阶段 2 + 写头期间若断电，旧头仍是 PMG3 但旧记录已被部分覆盖，旧校验和
将失败，下次开机会按空档案重建（丢失数据）。这是已知的 **短时间内断电风险窗口**，
迁移画面会显示 `DO NOT POWER OFF`。完整掉电保护需要双份存档/日志，未在本版实现。

### 5.4 回收站布局（v0.3.2，PMG4 扩展区）

| 平面偏移 | 长度 | 内容 |
|---|---|---|
| 20,416 (0x4FC0) | 4 | MAGIC `"BIN1"` |
| 20,420 | 1 | head：下一个写入位（0..15 循环） |
| 20,421 | 1 | 独立 XOR 校验和（种子 0xA5，覆盖 head + 16×80B） |
| 20,422..20,431 | 10 | 保留 0 |
| 20,432..21,711 | 16×80 | 回收站记录（与槽位记录格式完全相同） |

- 删除槽位时先把记录压入回收站（`head` 处，覆盖最旧），再清槽位；
  最新一条在 `(head-1) & 15`，界面最新在前。
- 恢复时写入**第一个空槽**（不保证原槽号），随后清空回收站条目。
- 回收站有**独立校验和**，不参与 0..20415 的主库校验和；`vault_commit` 不受影响。
- **懒初始化**：回收站区域与迁移暂存区（12,368..32,767）重叠，为不影响 v0.3 迁移，
  ROM 在首次打开回收站或首次删除时才检查 MAGIC 并初始化（`bin_load`）；
  迁移完成时暂存区清零也会顺带清掉旧回收站，迁移后首次删除会自动重建。
- 全库擦除（`vault_clear_slots`）会连回收站一起清零，彻底销毁已删记录。

## 6. 显示与输入系统

- **字体**：`genfont.py` 程序化生成 **96 个** 8×8 正色 tile（ASCII `0x20..0x7F`，
  含小写字母，下伸部用第 8 行）；**96 个反白字模在开机时由正色字模生成**：
  - tile 96..127 → VRAM `0x9600` 起；tile 128..191 → VRAM `0x8800` 起。
  - 这是 GBDK 的 BG tile data 基址 `0x9000` / 有符号寻址（LCDC.4=0）下的正确位置；
    旧 V0.3.3 把它们连续写到 `0x8600`：tile 128..191 恰好落在 `0x8800`，但
    tile 96..127 错位（应从 `0x9600` 读），空格/数字/部分小写的反白会读不到；
    再加上旧反白 `XOR` 双平面 + `BGP=0xFC` 会把选中态变成黑底黑字。V0.3.4
    分段写入正确地址并使用 `low=~glyph`、`high=0`，恢复黑底浅字。
  - 反白 tile 使用 low plane = `~glyph`、high plane = `0`；在 `BGP=0x9C` 下为
    黑底（索引1）+ 最浅字（索引0）。
  - `tile_of()` 映射字符→tile 序号；`put_fixed(x,y,s,width,inv)` 负责定宽写屏与反白。
- **调色**：DMG 四阶绿，`BGP=0x9C`：索引0=最浅 `(239,255,222)`，1=黑 `(24,52,66)`，
  2=中绿 `(173,215,148)`，3=暗绿 `(82,146,115)`。
- **图形 PIN 界面（V0.3.5）**：纯 BG tile，无 sprite，所有图形 tile 在开机
  `DISPLAY_OFF` 期间由 `gen_ui_tiles()` 生成。
  - **布局**：row0 = `SECRET VAULT` + 整行横线；row1 = 动作标题
    （`ENTER PIN` / `NEW PIN` / `CONFIRM PIN` / `OLD 4-DIGIT PIN`）；
    rows2..4 = 6 个 **3×3** 图形分格框；rows5..16 = 3×4 立体键帽键盘；
    row17 = `B=DEL  START=OK`。
  - **9-slice 立体框**：tile 192..200 为左上/上/右上/左/填充/右/左下/下/右下；
    每个键为 **6×3 tile**，每个 PIN 框为 **3×3 tile**，共用同一套边框。
  - **PIN 框位置**：6 位时 x=1,4,7,10,13,16；每框 3 tile 宽，6 框共占 18 tile
    （左右各留 1 tile），框与框的边框相邻、不设空白间隔 tile；迁移旧档 4 位时
    从 x=4 开始。当前输入位显示 `_`，已输入位显示数字。
  - **中心数字**：tile 201..210 为 0..9 的整字居中字模（中绿底 + 黑字），
    211 为下划线；空框中心使用 tile 196 填充。数字不再拆成左右两半。
  - **键帽标签**：tile 223..237 为 `0-9/C/L/R/O/K` 的键帽底色字模；
    普通键使用中绿底黑字，选中键使用反白字模（tile+96，如 `1` → 113）。
  - **整键反白**：tile 212..220 是 192..200 的 9-slice 变体，生成时把填充色
    索引 2（中绿）替换为索引 1（黑），亮边/暗边保留。选中时整个 6×3 键帽
    用 212..220 绘制，配反白标签形成**整键黑底浅字**；光标移动时只重绘旧/新两键。
  - **标题/横线**：tile 238..247，每个 tile 的最后一行是实心横线；
    row0 整行填 238 后覆盖标题序列，横线贯穿整行。
  - **按键**：十字键移动；`A` 输入数字/激活 CLR·OK；`B` 退格一位；
    `START` 确认；`CLR` 清空全部已输入数字。长度参数化（常规 6，迁移旧 PIN 4）。
- **虚拟键盘 v2**：三种模式——大写 / 小写（`Aa` 键切换，字母格原位换字形）/
  符号页（`SYM` 键切换，40 格全 ASCII 标点）；底行 5 键
  `Aa / SYM(ABC) / SPACE / DEL / OK`；上下行越界自动收拢列号。
- **随机密码生成器**：密码页 `SELECT` 生成（细节见 §7.7/§7.9），长度与是否含符号
  可在 SETTINGS 里配置（12/16/24/32 位，默认 16 + 符号 ON），再按重掷；
  生成后可继续手动增删改。
- **输入窗**：15 格窗口；超过 14 字符自动向左滚动，光标 `_` 恒定可见
  （支撑 36 位长密码、20 字符标签/用户名）。
- **列表滚动窗口**：12 行可视 + 边缘滚动；标题右侧常显 `nnn/255` 位置；
  行宽 18（3 位编号 + 空格 + 14 字符标签/用户名窗口）；空槽显示 `EMPTY`，
  空用户名显示 `-`；`LEFT/RIGHT` 整页翻 **12 条**；上下按住连续滚动；
  `SELECT` 切换标签/用户名视图并持久化；选中行超长标签跑马灯（§4.2）。
- **详情页**：标签/用户名各一行 20 格；密码两行 20+16 格；提示行固定在 15/16/17。
- **自动锁屏**：解锁后 `idle_start()` 启动 TIMA@4096Hz（回绕 62.5ms），
  菜单/列表/详情/编辑/设置/回收站/改 PIN 每轮轮询 `idle_poll()`；达到
  `分钟数×960` 次回绕即返回 1 触发回锁；任意按键清零重计。
- **输入循环（重要）**：所有交互画面采用 **忙轮询 `getkey()`（读 `joypad()`）**，
  **坚决不依赖 HALT/中断帧同步**——原因见 §7.2。列表页另改为逐帧忙轮询 + 按下沿判定，
  避免 serverboy 丢单帧点按；跑马灯/连滚/自动锁屏节拍用硬件 TIMA。

## 7. 关键实现决策与踩坑记录

### 7.1 为什么放弃 GB Studio、转 GBDK-2020 C

需求是“**直接产出可在真机运行的 ROM 文件**”。GB Studio 路线（docs/01~04 的规划）
在“数组/间接寻址/存档模型”上要绕大量插件与 GBVM 技巧；而 GBDK-2020 C 可以
直写 SRAM、直控 tile 与 timing，交付一 32KB 单文件 ROM，故中途转向并保留旧规划
稿仅作设计参考。

### 7.2 输入不能依赖 HALT 帧同步（详情页 B 键之谜）

- **现象**：详情页按 B “有时不返回”，且各界面偶发丢单帧点按。
- **根因**：serverboy 模拟器中，按键按下会触发 `JoyPadEvent` 并将
  `remainingClocks` 置 0（本意是唤醒 STOP），这**打断了 GBDK `wait_vbl_done()`
  的 HALT 等待**；单帧点按是否被吃到取决于模拟器量子与 HALT 的相位边界。
  真机虽无此问题，但为了“同一份代码在真机与模拟器行为一致”，全部改掉。
- **解决**：所有输入画面（含详情页的“按住 A 显示明文”）改成纯 `joypad()` 忙
  轮询 + 按下沿判定；v0.3.1 的列表页也改为逐帧忙轮询，跑马灯仅借用 TIMA 计时。
- **经验**：本 ROM 中唯一的“帧时间源”是硬件（定时器/画面绘制节奏），代码不
  做 `wait_vbl_done` 之类的帧同步，逻辑对“每帧读几次按键”完全不敏感。

### 7.3 锁定页长按计时：从 LY 采样 → 硬件定时器 TIMA

- **初版**：读 `LY_REG` 数 VBlank 边沿（`ly>=144 && prev<144` 每帧一次），阈值 182 帧 ≈ 3 秒。
- **现象**：真机没验，但模拟器里 230 帧长按只累计出 ≈76 次边沿 → 永不触发擦除。
- **排查**（`debug-lock2/3/4.js` 探针）：serverboy 的 LY 序列在 VBlank 处被压缩，
  “143→146” / “152→0” 等边沿常被跳过，无法可靠计数。
- **解决**：改用**硬件定时器**：`TAC=0x04`（4096Hz，即每 1024 CPU 周期 TIMA+1），
  8 位回绕一次 = 256 tick ≈ 62.5ms；**48 次回绕 = 整 3.000 秒**。
  轮询开销远快于 tick 间隔，回绕不会漏读；松开任一键立即清零重计。
- **复用**：v0.3.1 列表跑马灯也使用同一 TIMA 节拍（8 次回绕起始停顿、
  2 次回绕每格、12 次回绕端点停顿）。

### 7.4 put_fixed 乱码

早期反白行出现乱码：定宽写入时 tile 索引/尾随填充处理错误。修复后通过
`dump 08-detail-reveal`（“PASS: ABC”整行正确）与菜单高亮 dump 验证。

### 7.5 测试基建适配 serverboy 的要点（供后续改进复用）

- 屏幕断言读的是**模拟器建模的 VRAM**：tilemap 在
  `core.BGCHRBank1[(0x9800 + y*32 + x) & 0x7FF]`（`getMemory()` 读不到这两块）。
- 按键语义：`pressKey` 后需 `doFrame()`，**每帧结束强制松键**；所以：
  - `tap` = 单帧点按（一次输入事件）；
  - `hold` = 每帧重新按下（仅对忙轮询界面有效）。
- 一次 `doFrame()` = 一个模拟量子 ≈ 33,554 周期（≈0.478 个真帧），一切“秒数”
  按周期换算，不能按 doFrame 次数算。加载/全量校验/Toast 等操作要留足等待帧数
  （v0.3.1 的保存路径测试等待上限已放宽到 1200 帧）。
- 打开详情页的那次 A 点按会在同一模拟帧内被详情页看到，可能立刻进入“按住 A 显示明文”；
  测试在打开详情后应空跑几帧再断言打码/操作组合键。

### 7.6 v0.2 大改版要点（36 位密码 + 三模式键盘 + 192-tile 字体）

- **SRAM 格式升级**：密码 12→36 字节，记录 23→47 字节；MAGIC 升为 `"PMG2"`。
- **字体扩容**：tile 预算从 128 扩到 192（96 正常 + 96 反白），新增小写字母
  与 `` ` { | } ~ `` 等字形；反白偏移 = +96。
- **三模式键盘**：`Aa` 切大小写，`SYM` 翻符号页，方向键越界自动收拢列号。
- **长密码显示**：详情页两行×20 格；输入行 15 格带左滚动窗口。
- **测试镜像**：`smoke.js` 的 `typeText` 升级为键盘状态机，逐字符/逐模式变更
  都以屏幕单元格字形/高亮验证。

### 7.7 v0.3 大改版要点（255 槽 + 32KB RAM banking + 随机密码生成器）

- **MBC1 RAM banking**：上电先写 `0x6000 = 0x01`；此后 `0x4000` 写体号才生效。
- **卡带头部的 RAM 大小**：GBDK `-Wm-ya<n>` 传的是 **RAM 存储体个数**；
  `ya1 → 0x149=0x02`（8KB），**`ya4 → 0x149=0x03`（32KB）**。
- **平面地址 = 体号×8192 + 体内偏移**：存档文件即 32KB 平铺，索引与平面地址一一对应。
- **无整库镜像**：改为定点读写 + 提交时全量重算校验和。
- **随机密码生成器**：先保证大写/小写/数字/符号各 1 个，再随机填充到 16 位，
  最后 Fisher-Yates 洗牌；字符集 70 个（`A-Z` 去 `I O` / `a-z` 去 `l` / `2-9` /
  13 个符号 `.-_@!#$%&()?+`，避开视觉混淆字符 0 O 1 l I）。熵源：按键 tick +
  按键掩码 + `DIV`/`LY` 抖动 + 16 位 LCG（`x*251+33`）。
- **列表滚动窗口**：12 行 + 边缘滚动；`LEFT/RIGHT` 跳 8 条；ADD 自动占第一个空槽。
- **测试基建三个坑**：verify 必须带行内容；空输入行光标 `_` 在 x=1，判空要跳过光标；
  单帧 tap 会丢，必须 `tapUntil` 重试。

### 7.8 v0.3.1 改版要点（本次交付）

用户需求：标签 8→20、新增用户名（20，可空）、PIN 4→6、**必须继承 v0.3 存档**、
长标签必须滚动而不是截断、编辑用 SELECT+START 组合键避免误触。

- **存储扩容**：记录 47→80B（used/llen/label[20]/ulen/user[20]/plen/pass[36]），
  255×80 = 20,400B + 16B 头 = **20,416B**，跨 3 个 8KB 存储体；`-Wm-ya4` 不变。
  头部改为 `PMG4`，PIN 占 6B @4..9，TRIES @0x0A，CHK @0x0B，FLAGS @0x0C。
- **6 位 PIN**：`PIN_LEN=6`，输入组件长度参数化；迁移旧档时用 4 位模式。
  注意 PIN 混淆仍是逐位 `(d+7)%10`，6 位 PIN 直接多存 2 字节，不做哈希。
- **迁移（重点）**：识别 `PMG3` + 旧校验和 → 旧 4 位 PIN（沿用旧错误次数）→
  两次设置新 6 位 PIN → 阶段 1 写到存储体 3 高区暂存（12,368..32,767，
  旧档 0..12,000 不受影响）→ 阶段 2 升序搬回 16..20,415 → 写 PMG4 头 →
  清零暂存区。旧标签/密码逐字节保留，用户名留空。
  故意**不把 4 位 PIN 补零成 6 位**，避免用户以为旧 PIN 还能用。
- **列表跑马灯**：行宽 18（x=1 起，`nnn ` + 14 字符标签窗口）；选中行超出 14 字符时
  停 0.5s → 每 0.125s 左移一格 → 尾部停 0.75s → 反向回滚；切行立即复位；
  只重绘选中行，避免整屏闪烁。列表输入从阻塞 `getkey` 改为逐帧忙轮询 + 按下沿。
- **详情页新布局**：LABEL 行 3、USER 行 5、PASS 行 6、密码行 7/8；
  提示 `A=REVEAL B=BACK` / `SEL+START=EDIT` / `START=DELETE`。
- **组合键编辑**：详情页同时按住 SELECT+START 才进入编辑（先等两键松开，再开三页预填）；
  单按 START 仍是删除 + 二次确认。三页均预填原值，START=OK；
  标签/用户名页 SELECT=ESC，密码页 SELECT=GEN；保存 toast `UPDATED`。
- **性能**：全量校验和/清空改为按存储体直接扫描 + `memset`，避免 20KB 逐字节
  `rb/wb` 调用；`src/main.c` ROM 占 13,912B（85%），仍富余 2,472B。
- **测试扩展**：四流程 105 条 → **五流程 162 条**，新增：
  20 字符标签/用户名、可选空用户名、跑马灯尾部/回滚、SELECT+START 编辑与预填、
  单按 START 删除回归、255 槽跨 3 体（20416B）校验和、v0.3 存档迁移（错一次旧 PIN、
  新 PIN 654321、逐字节密码保留、暂存区清零、迁移后补填用户名、重开机验证）。

### 7.9 v0.3.2 改版要点（本次交付）

用户需求（四项 + 兼容）：① 列表支持 `SELECT` 切换标签/用户名、按住连滚、左右翻页；
② 生成器可选 12/16/24/32 位、符号开关并记住；闲置 1/2/3/5/10 分钟自动回锁；
③ 保存改用增量校验和提速；④ 删除进 16 条回收站防误删。继续支持 v0.3（PMG3）迁移。

- **列表 UX**：`SELECT` 切换视图并存 0x0F（空用户名显示 `-`）；`LEFT/RIGHT` 整页
  `LIST_PAGE=12` 条；按住上下连滚由 TIMA 回绕计时驱动 —— 首延迟 6 次回绕（≈0.375s），
  之后每 2 次回绕（≈0.125s）走一格，松开立即停。
- **生成器设置**：`GEN_LENS = {12,16,24,32}`、`GEN_ALL_NS`（无符号 57 字符集）+
  `GEN_ALL`（70 字符集）；设置存 0x0D（bit0-1 长度、bit2 符号、bit7 有效），
  旧 v0.3.1 存档有效位为 0 → 默认 16 位 + 符号 ON。
- **自动锁屏**：TIMA@4kHz 回绕 62.5ms，1 分钟 = 960 次回绕；设置存 0x0E
  （1/2/3/5/10 分钟，默认 3）；`ui_getkey()` 超时返回 0，各交互函数返回 `uint8_t`
  （1 = 自动锁屏），主循环据此回 ENTER PIN。改 PIN 画面通过 `pin_idle` 标志同样计时
  （锁屏时新 PIN 未保存）；`idle_stop()` 顺带清零详情缓存 `cur`，避免明文残留。
- **增量校验和**：RAM 缓存 `vault_chk`；`slot_write/slot_clear` 读旧字节 XOR 新字节差分
  更新，`header_patch/settings_save` 增量更新 3 字节设置，`vault_commit()` 只写回缓存；
  上电仍全量校验一次，迁移/首次设置/擦除用 `header_save()` 全量重算。

### 7.12 v0.3.5 → v0.3.6 存档安全 / 旧 PIN / RNG / 回收站 / 快速锁定 / UI（当前交付版）

V0.3.6 不改变 PMG4 存档格式，V0.3.1–V0.3.5 存档直接加载；PMG3 迁移保持。
本轮重点是“**任何异常都不能静默清空**”，以及补齐日常使用/视觉细节。

- **损坏存档保护**：
  - `vault_load()` 返回值拆成 `LOAD_EMPTY / LOAD_OK / LOAD_LEGACY / LOAD_CORRUPT /
    LOAD_UNSUPPORTED`。只有前 4 字节全为 `0x00/0xFF` 才视为空白卡带。
  - PMG4 MAGIC 存在但校验失败 → `SAVE CORRUPT`；未知 MAGIC → `UNSUPPORTED SAVE`。
    两者都**只读**，不调用 `setup_pin()`，不会自动 `vault_clear_slots()`。
  - 恢复画面：只读扫描 used 标记且长度合理的记录并显示数量；`A=RETRY` 重新读取；
    `START` 进入擦除确认，再按 `A` 才调用 `vault_wipe()` 重建 PMG4 头。
  - smoke 流程 0 验证：停留 120 帧、RETRY、进入擦除确认前 SRAM 字节完全不变。
- **旧 PIN 验证**：`CHANGE PIN` 改为 `OLD PIN → NEW PIN → CONFIRM PIN`。
  旧 PIN 错误显示 `WRONG PIN` 并返回菜单，不增加解锁错误次数、不写存档；
  旧 PIN 正确后才允许设置新 PIN。自动锁屏逻辑覆盖旧/新 PIN 输入。
- **RNG 改进**：
  - 开机 `rng_boot()` 混入 `DIV_REG`/`LY_REG` 并多次搅拌，替换固定 `0xACE1` 初态；
  - 每次生成密码再混入当前 `DIV/LY`；键盘事件继续混入按键时机；
  - `rng_below(n)` 用拒绝采样去掉 `256 % n` 尾部偏差；
  - 仍保证至少 1 个大写、1 个小写、1 个数字，符号开启时至少 1 个符号，再做
    Fisher-Yates 洗牌。**明确声明：这不是密码学安全 RNG。**
- **回收站**：保留 `A=恢复`；新增 `SELECT=永久删除单条`、`START=清空全部`，
  两者都有 `A=YES B=NO` 二次确认。单条删除只清零该 80B 记录并更新独立校验和；
  清空调用 `bin_reset()`，head=0、16 条记录全零、MAGIC/校验和重写。
- **快速锁定**：菜单/列表/详情/设置/回收站同时按 `B+SELECT` 返回 PIN 画面。
  没有采用“长按 B 1.5 秒”，因为 B 在列表/详情/回收站同时是“返回/删除”；
  组合键避免延迟返回，也避免输入画面误触。文本/PIN 输入画面不启用。
- **UI 刷新**：
  - 复用 tile 192..200 的 9-slice 边框，新增标题/菜单/列表/设置/恢复面板；
  - 新增 tile 248..255 的 8 个小图标（列表/加号/钥匙/锁/垃圾桶/齿轮/盾/警告）；
  - 菜单：图标 + 全宽反白选中条；列表：页眉 `B+SEL=LOCK` + 封闭面板 +
    14 字符标签窗口（左右边框保留，跑马灯阈值相应改为 14）；
  - 详情：字段反白标题 + 小图标 + 上下分隔线，密码区仍为两行 20+16 格；
  - 回收站：反白标题栏 + 空状态图标；标题画面增加面板与盾牌图标；
  - PIN 画面（V0.3.5 的 3×3 分格框/整键反白）保持不变。
- **ROM / 测试**：ROM0 16,043B（余 341B），ROM1 2,704B（余 13,680B），仍为 32KB；
  **255/255 全绿（约 40 秒）**。新增流程 0（11 条）、流程 G（11 条），
  流程 F 扩到 62 条。最终 ROM SHA-256 = `82cbc208cdde91ee90d971112b3fea9e9337dab10814b140b2575ff8859430c2`。
- **真机状态**：V0.3.6 尚未烧录验证；按 §9.1 清单执行，重点测试损坏存档恢复、
  B+SELECT、旧 PIN 修改、回收站清空和面板/图标在 DMG 上的对比度。

## 9. 构建与烧录

编译选项要点（见 `build.sh`）：

- `-Wm-yt0x03` 卡带类型 = MBC1+RAM+BATTERY；

- `-Wm-ynPASSMGR` 卡带标题；`-Wa-l -Wl-m -Wl-j` 输出列表/map/符号（排查用）。

**真机烧录**：支持电池存档的卡带（EverDrive-GB、EZ-Flash Jr、可烧录复刻卡等）

**注意卡带 SRAM 容量 ≥32KB**（见 §10 限制 4）。

### 9.1 V0.3.6 真机验收清单（建议按顺序）

1. **先备份**：用烧录器 dump 当前 32KB SRAM 存档；确认电池有电。
2. 烧录 `build/passmgr.gb`，上电确认标题显示 **V0.3.6**。
3. 新卡/空档：设 6 位 PIN，检查 6 个 3×3 加宽分格框、数字整字居中、选中键整体黑底浅字、

## 10. 已知限制（诚实声明）

1. **非加密**：SRAM 明文存储（PIN 仅 +7 混淆）。任意读卡器可 dump 全部密码。
   这是“仪式感工具箱”，**不要存真实重要密码**。
2. 容量：255 槽 / 标签 20 字符 / 用户名 20 字符 / 密码 36 字符；无搜索、无分类、无时间戳。
3. 无导入导出；V0.3.6 起改 PIN 需要先验证旧 PIN（已解锁状态下）。
4. **卡带要求 32KB SRAM**：ROM 头声明 0x149=0x03。若烧录卡/复刻卡的存档芯片
   只有 8KB（且不按头部虚拟化），高编号槽位可能读回错误（校验和不通过会被
   判为空档案）。EverDrive-GB / 主流模拟器均支持 32KB 存档。
5. **存档格式**：V0.3.1–V0.3.6 均为 `PMG4`（设置区位于 0x0D..0x0F）；
   **仅支持 v0.3（PMG3）迁移**。未知格式显示 `UNSUPPORTED SAVE`，不再静默重建；
   PMG4 校验失败显示 `SAVE CORRUPT`，只有显式确认才擦除。
6. **迁移掉电窗口**：阶段 2 与写新头期间断电可能丢失旧档（见 §5.3）；画面会提示
   `DO NOT POWER OFF`。完整双份/日志式存档未实现。
7. DMG 渲染模式，未使用 GBC 增强（调色板/双速）；ROM 总计 32KB（MBC1，2 bank），
   ROM0 16,043B（余 341B），ROM1 2,704B（余 13,680B）。新增代码继续利用 ROM1 空闲区；
   ROM1 代码依赖 MBC1 模式 1 下 0x4000 固定映射 bank 1，未引入跨 bank 调用。
8. 校验和只防意外损坏，不防篡改；V0.3.6 遇到校验失败会停在恢复画面而不是把存档当空档。
   写入过程掉电仍可能半写；真正的双头/日志式恢复留到 V0.3.7。
9. **删除 ≠ 立即销毁**：删除的记录会进入回收站保留（最多 16 条，超出后覆盖最旧），
   意在防误删；V0.3.6 可在回收站用 `SELECT` 永久删除单条、`START` 清空全部，
   也可使用 SYSTEM LOCKED 的整卡擦除。
   SRAM 是明文存储，旧记录在被覆盖前仍可被 dump 读到（见限制 1）。
10. **V0.3.6 真机待验证**：当前视觉与功能仅在 serverboy 模拟器通过（255/255）；
    V0.3.2–V0.3.5 也未单独做真机验收。首次烧录前务必备份存档，并按 §9.1 逐项验证。

## 12. V0.3.7 规划（记录，不在 V0.3.6 实现）

V0.3.7 的目标不是“把整个库镜像两份”（当前 32KB MBC1 SRAM 已用 21,712B，
只剩 11,056B，255×80B 的完整镜像需要 20,416B，放不下），而是用**可恢复的写入协议**
消除半写风险：

- **PMG5 头**：新 MAGIC + 格式版本 + 序列号 + 提交标记；
- **CRC16**：头部 CRC16 + 每条记录 CRC16（替代/补充当前单字节 XOR 全局校验和）；
- **双头 A/B**：两份小头部轮换写，带递增 sequence；上电选择 CRC 正确且 sequence 较新的头；
- **写前日志（write-ahead journal）**：在剩余 SRAM 中记录“将要修改的记录地址 + 旧值/新值 +
  CRC”，先提交日志，再写目标，最后清除日志；上电发现未清除日志则重放或回滚；
- **半写恢复**：记录 CRC 失败时只回滚该记录，不把整库判为空档；
- **迁移**：PMG3 / PMG4 → PMG5，保留旧档只读检测；迁移前先写日志；
- **测试**：模拟器注入“写一半断电”（截断写、随机字节、CRC 翻转、双头序列冲突），
  以及真机拔电/复位测试矩阵；
- **非目标**：全库双份镜像、PIN 加密、GBC 增强；这些继续留在候选池。

V0.3.7 需要新增约 2–4KB 代码和若干 SRAM 布局字段；当前 ROM1 余 13,680B，
空间足够，但仍应保持 32KB ROM 和 PMG4 只读兼容路径，避免再次发生“升级即清档”。
