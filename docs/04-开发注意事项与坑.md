# 04 · 开发注意事项：GB Studio 做"非游戏工具"的坑

> 针对 GB Studio 4.x（当前稳定 4.3.x）与 Game Boy 硬件限制。
> 按“踩坑概率 × 杀伤力”排序，前几条建议全部读完。

---

## 1. 变量系统：比你想的更"原始"

| 事实 | 后果 / 对策 |
|------|-------------|
| **GB Studio 没有字符串变量**。只有 16 位数字变量 | "密码"必须拆成"一个变量存一个字符的字符码"。这就是 `docs/03` 整个数据模型存在的原因 |
| 4.3 及更早：全局变量固定 **512 个**（$Variable0–511），编号即"地址" | 顺序重命名，**保证数据段连续**；不要中途插队 |
| 4.4 开发版：变量"按需创建" | 数据库范围内的每个变量都要真实创建，间接寻址才不会越界 |
| 变量是 **16 位有符号**，可存 −32768..32767 | 混淆时用 `+7`、异或都行，但别指望"字节溢出"特殊行为；负值在间接寻址里另有含义（指向栈） |
| 变量默认值 0，但 **读档会覆盖为存档值** | 所有"本次开机的运行时变量"（$LEN、$SEL、$PIN_LEN…）必须在启动场景里显式复位 |
| 场景的 On Init **每次进入都会执行** | 初始化逻辑要写成"幂等"的（重复执行也安全），或用 $BOOTED 之类的守卫 |

**数组模拟的两个关键操作（插件即在包装它们）**：

- `VM_SET_INDIRECT 地址变量, 值`：把值写进"编号 = 地址变量"的那个变量；
- `VM_GET_INDIRECT 目标, 地址变量`：反向读取。
- 地址 = `首变量编号 + 下标`，所以**元素必须连续编号**；计算地址需要
  "又一个变量"当临时量（Scratch），别和业务变量混用。

## 2. 存档（SRAM / 电池）：机制与预期管理

1. **卡带类型必须带 BATTERY**（Project → Settings → Cartridge Type：
   ROM Only + RAM + Battery 等），否则 `Game Data Save` 无从保存。
   模拟器里会生成 `.sav` 文件；SameBoy / BGB 记得开"battery save"选项。
2. `Game Data Save` 保存的是**全部变量 + 引擎运行状态**（线程、场景、角色、
   定时器、RNG），`Game Data Load` 整包恢复——所以：
   - 不需要"逐变量保存"，也不存在"只存一部分"；
   - 变量越多存档越大（本项目 ~1–2 KB / 槽，32 KB SRAM 的卡带完全无压力）；
   - 存档有 **3 个槽位**，别拿它当"多用户数据库"，多套数据请自己在一个存档里分区。
3. **不要幻想引擎自动读档**：开机流程永远由你的启动场景显式控制
   （`If Game Data Saved` → `Game Data Load`），否则"每次开机都要输 PIN"的体验会
   被上次的存档场景悄悄跳过（引擎恢复的可能是上次所在场景）。
4. **SRAM 写入寿命有限**（实机电池卡带尤其）。只在数据真正变化时存档，
   不要在每个按键循环里 `Game Data Save`。
5. 想要"清空所有数据"菜单项：`Game Data Remove` + 复位变量 + 重新初始化。
6. `Game Data Save` 事件的 **"On Load" 脚本**会在"以后某次读到这个槽"时执行——
   它适合放"读档后初始化"逻辑，但**不要**放一次性 UI 提示；本项目统一用
   启动场景显式 Load，避免心智负担。

## 3. 文本渲染：GB Studio 的文本不是"字符串"

1. **文本是直接写进 tilemap 的**（背景层或 overlay 层）。`Draw Text` 之后
   那一片瓦片就永久改变了；重绘要自己负责"擦干净"（我们用"永远画满 12 个 `%c` +
   尾部保留空格"来规避残留）。
2. **对话变量**是唯一把变量塞进文本的机制：
   - `$Var` 显示数字；`%c$Var` 显示字符码对应的字符（键盘输入就靠它）；
   - `%D5$Var` 固定宽度补零、`%d`、`%t`（文本速度）、`%f`（字体）；
   - 菜单选项文本、`Draw Text`、`Display Dialogue` 都支持这些 token。
3. 文本里的命令：`!Speed` / `!Instant` / `!Font` / `!Cursor`；换行 `\n`
   （在 GB Studio 4 的文本框里直接回车更直观）。
4. **字体是 ASCII 子集**：默认字体含大小写、数字、常见符号——**但绝无中文**。
   要中文得自备 8×8 点阵字体资产，且每字一格、每格一 tile：
   20×18 屏幕 ≈ 360 个字符/屏，字库 tile 会爆 VRAM，不建议。
5. `Draw Text` 的 **X / Y 是"值"字段**：可以选变量、可以写
   `9 + $LEN` 这样的表达式——动态光标、进度条一类的 UI 全靠它。
6. 文本动画速度用 `Set Text Animation Speed` 调到最快；
   对话框的打开/关闭也让 `Display Menu` 自己处理，别手写。

## 4. 输入：只有 8 个键 + 没有键盘重复

1. 可用的"按键"只有 `A B Start Select Up Down Left Right`。
   `Pause Script Until Input Pressed` 的 "Any of" 里**可以多选**方向键。
2. **没有系统级按键重复**（按住不会自动连发）。键盘每次按键移动一格，
   对 GB 的节奏来说完全够用；要做重复连发得自己写延时循环——不值。
3. `If Joypad Input Held` 是**每帧判断**的：不加约束会在按住时每帧触发。
   标准写法就是本项目的方法：`Pause Script Until Input Pressed` 先"等一次按下"，
   再用 `If Joypad Input Held` 分发。顺序错了会出现"按住 A 疯狂输入"。
4. `Display Menu` 自带 B 键返回（可选）和"最后一项为 0"的行为，
   工具类菜单直接复用。
5. 脚本**持续运行**期间，玩家的行走输入会被引擎暂停——这正是密码本想要的
   "模态 UI"效果；同时记得在场景里隐藏玩家、锁定摄像机。

## 5. 场景与 UI 组织

- 工具场景尺寸直接建成 **20×18 一屏**，避免摄像机滚动；场景类型用
  **Top Down / Adventure**（平台游戏类型有重力，会让角色乱掉），
  进场景后 `Hide Actor` 玩家，或 `Set Player Sprite Sheet` 为空。
- 场景 On Init 里把该屏所有动态元素画一遍（提示语、光标、指示箭头），
  保证"从任何路径返回"都呈现一致状态。
- 需要联动的界面（列表 ↔ 详情）靠全局变量（`$SLOT`、`$CHOICE`）传递，
  `Change Scene` 前赋值即可，没有"场景参数"概念。
- 大量重复的 12 组读写非常适合**复制粘贴 + 局部改字**；用了本项目的
  数组插件后这类机械劳动可以再砍一半。

## 6. 硬件与显示

| 限制 | 说明 |
|------|------|
| DMG 单色 | 背景只有 4 个灰度（0–3），调色板是"整屏"级的；想"高亮"按键请用文本反白 `\007\002` 或第二套调色板/精灵实现 |
| GBC | 可以做多套 8 色调色板；注意每个背景调色板仍受 tile 数量的约束，"16 色"是调色板层面的能力而非一张图任意 16 色 |
| 精灵 | 每行 10 个、全屏 40 个（8×8）。本项目用文本做主 UI，**不要**用 48 个精灵去画键盘 |
| 渲染节奏 | 一帧内 40 个 sprite / 大量 tile 重绘会拖慢；整行重绘（12 字符）无压力，但避免每帧重绘 |
| 帧率 | 单色 60fps；引擎的文本逐字动画在"最快"档基本是瞬时 |

## 7. 工程与调试

- **调试器**：窗内 Variables 面板可以实时看全部变量（把字符码翻成字符看），
  跑默认模拟器时 SRAM 存档会写着色恢复，重开调试器前记得清档验证"首次开机"路径。
- **常见编译报错**：
  - 插件用错变量类型（传了自定义脚本参数）→ 见插件 README「只支持全局变量」；
  - 变量名重名/断号 → 数组读写结果不对，检查连续段；
  - 忘记 `plugins` 目录结构 → 事件列表里看不到 "Password Manager" 分组。
- **版本差异速查**：
  - 4.3+：有 `Data Table Lookup`、`If Math Expression`、脚本侧栏等，本文默认能力；
  - 4.2 及更早：没 Data Table 时用 `docs/02` 第 6.4 节的 If 链替代；
  - 4.4 开发版：新增**真数组变量**（"For Each Array Element"、"len()" 等），
    本项目里所有 🧩 数组插件用法都可以被原生数组语法逐步替换，插件里的
    数据模型（连续段）可以无缝迁移。

## 8. 安全与产品诚实性（重要）

- 这是**复古玩具级**的密码本：SRAM 明文/弱混淆，任何读卡器/模拟器都能看到内容。
  **不要**把真实银行密码存进去；它的价值是"Game Boy 上的仪式感"。
- 加"PIN 彩蛋"、开机锁屏、输错锁机这些机制满足的是氛围而不是安全。
- 真机上电池没电 = 数据全丢，这本身就是"复古体验"的一部分：
  可以在启动画面里加一句 "BATTERY LOW? SAVE OFTEN." 的幽默提示。
